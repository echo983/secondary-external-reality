# 内容包交付格式 v0.1（谦虚版）

状态：够用就行，不追求完备，预期会改。这是三条内容来路（外部授权转换、原创手写、LLM 约束生成）共同交付的目标格式，不是某一个转换器的内部细节。

## 为什么不用 JSON/YAML

JSON 要求括号严格配对——一处漏了，整份文档全废，批量生成场景下代价被放大。YAML 靠缩进定层级，错误同样隐蔽且容易牵连整个文件。这份格式选择**按行分隔、无嵌套、局部可恢复**：一条记录写崩了，解析器跳到下一个记录标记就能救回其余部分，不需要整份重来。

## 格式规则（全部规则，就这么多）

文件是 UTF-8 文本，由若干条**记录**顺序组成。

1. 一条记录以 `=== <记录类型>` 开头（三个等号、一个空格、一个不含空格的类型名，比如 `place`、`entity`）。
2. 开头行之后，直到遇到 `---` 独占一行、或者下一条 `=== ` 记录、或者文件结束，中间每一行是 `key: value` 形式的刚性字段（key 不含空格，value 是这一行冒号后面的内容，掐头去尾空白）。空行在这个阶段直接跳过。
3. 同一个 key 出现多次 = 一个列表字段，按出现顺序累积（不需要数组语法）。
4. 遇到独占一行的 `---`，记录进入**自由叙述模式**：从这里开始，直到下一条 `=== ` 记录或文件结束，所有内容原样当作一段自由文本（保留换行，掐头去尾空行），不再按 `key: value` 解析——这段文本里随便写标点、冒号、逗号，都不需要转义。一条记录最多进入一次自由叙述模式；进入之后任何看起来像 `---` 或 `key: value` 的行都只是文本内容，不再有特殊含义。
5. `attrs` 字段的 value 用空格分隔若干个 `key=value`（比如 `attrs: openable=true open_state=closed`），承载引擎级刚性属性——这些值本来就是不含空格的短 token，不需要引号。

没有注释语法，没有嵌套记录（一条记录要引用另一条，直接写它的 `id` 当 value，比如 `place: yuhang-inn`），没有转义规则（除了自由叙述模式本身就是"不需要转义"的解决方案）。

## 记录类型（v0.1 只定义这两种，够 sdlpal 这次用）

- `place`：`id`（必填）、`zh`/`en`（名称）、`adjacent`（列表，邻接地点 id，可重复出现表示多条边）。
- `entity`：`id`（必填）、`type`（必填，引擎实体类型，比如 `door`/`person`/`container`）、`zh`/`en`（名称）、`place`（初始所在地点 id）、`attrs`（刚性属性）、自由叙述正文（性格/背景/外观，供 LLM 消费，不构成因果事实，除非之后被专门"晋升"）。

需要新记录类型（比如以后的 `relation`/`edge`）时再加，不预先设计。

## 校验规则（v0.1 只做最低限度）

- 每条记录必须有 `id`；
- `entity` 记录必须有 `type`；
- 缺字段、`key: value` 写错形状（没有冒号）等问题，记成一条错误（带上记录起始行号和序号），**不中断解析**——解析器返回"成功解析出的记录列表" + "错误列表"两样东西，调用方自己决定要不要接受部分结果。

## 明确排除（等真的需要再回来加）

- 类型系统/属性合法性校验（现在只检查"字段存不存在"，不检查"这个 type 允不允许这个 attrs key"——这个要接进内核时才有意义，现在内核还没消费这份格式）；
- 创作者友好性专项优化（先满足"能用"，人类编写体验的专门打磨留到之后）；
- 注释、转义、嵌套——都不做，做了就是过度设计。
