# sdlpal 数据格式研究记录

来源：sdlpal 引擎源码（`global.h`/`global.c`/`map.h`/`map.c`/`palcommon.c`/`yj1.c`），对照用户自己合法拥有的游戏数据验证。

## 已验证、可以直接用（`mkf.ts`/`yj1.ts`）

- **MKF 归档容器**：文件开头一个小端 uint32 给出头部总大小（= 4×(块数+1)），之后是每块的小端 uint32 偏移量数组，块 N 的字节范围是 `[offset[N], offset[N+1])`。
- **YJ1 压缩**：块内数据以 `"YJ_1"` 4字节签名开头，其后是哈夫曼树（叶子/内部节点标记 + 值字节）+ 分块压缩数据（哈夫曼编码字面量 + LZSS 回溯引用）。已对 `MAP.MKF` 全部 225 个非空块验证：解压后长度和块头声明的长度精确一致，抽查的瓦片值在 `map.h` 文档的位布局下解出的贴图序号合理。

## 已找到定义、还没解析验证的结构

- **`EVENTOBJECT`**（`global.h`）：地图上一个"物体/角色"的放置记录——坐标 (x,y)、层号、精灵图编号、触发方式（`TRIGGERMODE`：靠近/触碰，近/中/远几档）、状态（隐藏/正常/阻挡）、以及**两个脚本入口号**（`wTriggerScript`/`wAutoScript`，指向真正的脚本字节码，不是我们要的部分）。存在 `SSS.MKF` 第 0 块，最多 `MAX_EVENT_OBJECTS = 5500` 条（整个游戏，不是一个镇子）。
- **`SCENE`**（`global.h`）：场景记录——对应哪张地图（`wMapNum`）、进入/离开时执行哪段脚本（同样不是我们要的）、这个场景的 EventObject 从数组哪个下标开始（`wEventObjectIndex`）。存在 `SSS.MKF` 第 1 块，固定 `MAX_SCENES = 300` 条。
- **`OBJECT`/`OBJECT_DOS`**（`global.h`）：物品/魔法/敌人/玩家角色的系统记录（联合体，按类型 6~7 个 WORD 字段），存在 `DATA.MKF`，按类型分不同的块号（注释里提到过 `DATA.MKF #1` = 敌人、`#3` = 魔法）。
- **`SCRIPTENTRY`**：脚本字节码，操作码 + 3 个操作数，是 `EVENTOBJECT`/`SCENE` 里脚本入口号实际指向的内容——**明确不打算解析/复用**，这是这个项目要绕开的刚性预设演出逻辑。

## 对这个项目的取舍（对应 `docs/VISION-first-experience-instance-v1.0.md` §3 的复用边界）

**要**：`MAP.MKF` 瓦片网格（地理骨架）；`SSS.MKF` 的 EventObject 坐标/精灵/触发方式（"这里有什么"的花名册，不要它挂的脚本）；`SSS.MKF` 的 Scene 表（场景↔地图的对应关系，划场景边界用）；`DATA.MKF` 的角色/物品名字（当人物设定种子）；`M.MSG` 台词文本（当性格/背景素材，不当脚本跑）。

**不要**：`SCRIPTENTRY` 字节码本身；任何触发后"具体演出了什么"的逻辑。

## 规模参考

整个游戏最多 300 场景、5500 事件物体——远超一个镇子的量级。下一步真要提取余杭镇内容时，需要先定位"哪些场景/地图编号属于余杭镇"，只挑那部分，不是整体导入。
