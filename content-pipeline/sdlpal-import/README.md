# sdlpal 地图/实体数据导入管线

状态：初始搭建，未产出可用数据。
分支：`content-pipeline/sdlpal-import`（不合并回 `main`，直到管线真正能产出内核可消费的数据）。

## 隔离边界（重要）

这个目录是刻意和内核（`src/`）完全隔开的：

- 根目录 `tsconfig.json` 只编译 `src/**/*.ts` 和 `test/**/*.ts`，这个目录不在其中，`npm run build`/`npm test` 完全不会碰到这里的任何东西；
- 内核代码不应该 `import` 这个目录下的任何东西；这个目录下的代码在开发阶段也不应该 `import` 内核代码——两边只通过"这个管线的输出数据文件"单向联系，且只在管线真正稳定之后才会发生；
- 这个目录下的探索、格式反推、试错代码可以随便写、随便废弃，不需要遵守内核那边的测试覆盖率/设计文档纪律——直到某一天它产出的数据格式定下来，要被内核当作一个新的 fixture 真正接入时，那一步才需要正式设计文档，且发生在内核那边，不是这里。

## 版权边界

`game-data/` 用来存放从用户自己合法购买的《仙剑奇侠传》拷贝里复制出来的原始游戏数据文件——**这个子目录必须被 gitignore，任何时候都不能提交到版本库**，不管是本分支还是以后合并。sdlpal 本身的引擎代码是开源的，但游戏数据是软星的商业资产，属于用户个人合法拥有的范围，不属于这个仓库可以分发的范围。

## 现状

- 已确认：sdlpal 是纯播放器/解析引擎，不带游戏数据；数据来自用户自己的正版拷贝（Steam 版）；
