# MVP 操作组合与部分成功计划 v0.3

日期：2026-08-23  
状态：执行基线

## 目标

一个 `ttd` 可以包含多个有序动作。每个已经发生的动作都是世界历史；后续动作失败时，系统不得把前序事实回滚成“什么都没发生”。

目标示例：

```text
ttd: 我打开抽屉，拿出钥匙，然后去开门
```

执行模型：

```text
规范化为 [open drawer, take key, open door]
→ step 1 验证、陪审、提交
→ 从新状态执行 step 2
→ step 2 验证、陪审、提交
→ 从新状态执行 step 3
→ step 3 验证、陪审、提交
→ 汇总玩家可见回应
```

## 部分成功

若 step 3 失败：

- step 1、step 2 的提交继续有效；
- step 3 不写入失败的世界变化；
- 回应明确前序动作已经发生，后续动作未完成；
- 重启后恢复到最后成功步骤的状态。

首步失败时不产生世界提交，并沿用当前保守失败响应。

## MVP 约束

- 只处理用逗号、分号、句号、`然后/再/then/and then` 明确分隔的动作；
- 每个子句必须能进入既有确定性动作域；
- 每一步使用独立 `commit_sequence` 和 revision guard；
- 多步序列暂不提供跨步骤数据库事务，因为那会破坏“已经发生的前序动作”；
- LLM逐步审查，不一次决定整条行动链；
- 最终自然语言汇总无权改变任何步骤的提交结果。

## 验收

- 完整成功：打开抽屉→拿钥匙→开门；
- 部分成功：打开抽屉→拿钥匙→关抽屉→尝试把钥匙放入关闭抽屉；
- 首步失败：从关闭抽屉直接拿内部钥匙，不产生提交；
- 每一步读取前一步提交后的新状态；
- 部分成功后重启，世界恢复到最后成功步骤；
- 单动作、开门和纸条回归保持通过；
- 真实 SSH 与 Workers AI 复合输入通过。
