# MVP 操作组合与部分成功 v0.3

日期：2026-08-23  
状态：已实现

## 执行语义

复合 `ttd` 先按显式边界拆分为原子步骤。`write_and_hide`、`read` 和 `open_and_observe` 保留为不可再次拆分的既有复合语义。

每一步独立执行：

```text
读取最新 world_commits
→ 重建当前状态
→ 前置条件与候选验证
→ Mistral 陪审
→ revision guard
→ LanceDB 提交
→ 下一步读取刚提交的新状态
```

因此，后续步骤不能基于整条命令开始前的陈旧快照。

## 完整成功

输入：

```text
我打开抽屉，拿起桌上的钥匙，然后去开门
```

规范化步骤：

```text
open(drawer-1)
take(key-1)
open(door-1)
```

产生连续的 3 条提交。最终钥匙 `held_by self`，门为 `open`。

## 部分成功

输入：

```text
我打开抽屉，拿起桌上的钥匙，然后关上抽屉，再把钥匙放进抽屉
```

前三步成功并提交。第四步因抽屉已经关闭而在写入前失败：

- 已提交的打开、拿取、关闭不会回滚；
- 没有伪造 `put_inside` 提交；
- 返回 `partial=true` 和前三个 commit package；
- 玩家回应明确说明前序动作已发生，失败子句未完成；
- 重启恢复后钥匙仍由主体持有，抽屉仍关闭。

首步失败时仍按原行为抛出失败，不产生“部分成功”或世界提交。

## 验证

- 69 项自动测试全部通过；
- 原有单动作、纸条、开门、LanceDB 和 SSH 测试无回退；
- 真实 SSH + Workers AI 完整成功和部分成功回归通过；
- 两条真实复合命令总耗时约 16.2 秒；
- 完整链 3 条提交：钥匙在手中，门打开；
- 部分链 3 条提交：钥匙在手中，抽屉关闭；
- 关闭并重新打开 LanceDB 后部分结果保持一致。

## 当前边界

- 分句只识别明确标点和有限连接词；
- 每一步单独调用陪审，长序列延迟近似线性增长；
- 多个 step commit 尚未共享独立的 root request/turn ID，只通过连续顺序和返回的 `commitPackages` 聚合；
- 失败步骤目前不写入 WorldTruth 事件账本，只在本次回应中报告；
- 尚未实现“动作尝试本身发生、但效果失败”的通用失败候选；
- 没有跨步骤规划优化或并行执行，所有可能改变同一世界的步骤严格顺序执行。

下一阶段应优先增加 root turn identity 与结构化失败/尝试事件，使部分成功可以在重启后从审计记录本身还原，而不只从成功提交和即时回应推断。
