# Secondary External Reality · MVP 架构决策 v0.1

状态：讨论基线，已采纳

本文记录第一阶段 MVP 已达成的架构共识。目标不是一次实现完整 GWA，而是先建立一个可持续深化的最小世界交互闭环。

## 1. 产品目标

使用方通过普通 SSH 客户端连接服务。终端显示：

```text
ttd:
```

`ttd` 表示 **try to do**。用户输入的是主体意识发出的意图，而不是直接修改现实的命令。

例如：

```text
ttd: 下床去开门
```

这表示主体尝试下床并开门。世界需要根据身体、空间、对象及既有历史独立裁决。行动可能成功、部分成功、失败，或者产生非预期后果。服务最终使用与用户输入相同的语言，返回可信的“第二外部现实回应”。

## 2. MVP 边界

第一阶段优先完成：

- 普通 SSH 纯文本会话；
- `ttd:` 交互循环；
- 单次只处理一个主体意图；
- 小范围场景和基本身体状态；
- 基本实体、实体关系、事件和回合记录；
- Cloudflare Workers AI 提供真实 LLM 推理；
- 并行生成/验证，但只有一个收束与提交边界；
- 与输入相同语言的自然语言现实反馈；
- 仅提交本次行动闭环必需的最小事实。

第一阶段不追求：

- 完整宇宙模拟；
- 完整 GWA Query Triage 形式化实现；
- 大规模多模态 canonical facts；
- 一次性构建完整认识论图、解释系统或长期剧情规划器；
- 为未进入当前闭环的世界区域预生成大量事实。

## 3. 总体处理闭环

```text
SSH 输入
  → 识别语言与主体意图
  → 从 LanceDB 精确读取世界事实，并进行辅助语义检索
  → 生成少量现实结果候选
  → 两个并行可信性验证工位
  → 确定性收束器选择、降格或拒绝候选
  → 原子式归档必要的实体/关系/事件变化
  → 以同语言生成自然现实反馈
  → ttd:
```

用户输入只拥有“提出尝试”的权限。诸如“我打开门”应按“我试图打开门”处理，不能直接判定门已打开；用户关于外部世界的断言也不能直接成为 WorldTruth。

## 4. LanceDB 存储决策

MVP 从第一版开始使用 LanceDB，统一承载结构化记录、自然语言内容和 embedding。

LanceDB 同时支持两类读取，但两类读取的权力不同：

1. **精确读取**：按稳定 ID、关系、版本及事件引用读取世界事实；
2. **语义检索**：定位可能相关的实体、事件、记忆和历史上下文。

向量检索只负责寻找候选记录，不负责决定世界中什么是真的。世界一致性必须依靠稳定 ID、结构化字段、提交记录和版本检查。

### 4.1 `entities`

```text
entity_id
entity_type
canonical_name
aliases[]
attributes_json
state_json
location_id
created_at
updated_at
revision
embedding
```

`attributes_json` 保存相对稳定属性，`state_json` 保存当前可变状态。实体使用稳定 ID；名称和自然语言描述不能代替身份。

### 4.2 `relations`

```text
relation_id
subject_id
predicate
object_id
qualifiers_json
valid_from
valid_until
status
revision
embedding
```

实体关系是一等记录，不应只埋在描述文本中。典型关系包括 `located_in`、`sitting_on`、`connects` 和 `part_of`。

### 4.3 `events`

```text
event_id
turn_id
event_type
participants[]
causes[]
effects_json
location_id
timestamp_world
commit_status
summary
embedding
```

事件采用追加式记录。事件与当前状态分离：例如“尝试站起但失去稳定”是事件，事件完成后的姿势是实体当前状态。

### 4.4 `turns`

```text
turn_id
session_id
raw_input
input_language
normalized_intent
context_snapshot_refs[]
candidate_outcomes[]
validation_reports[]
committed_event_ids[]
response
created_at
```

`turns` 保存一次 `ttd` 的完整处理轨迹，用于审计、调试和重放。被否决的候选可以留在回合记录中，但不得进入 WorldTruth。

### 4.5 `world_meta`

最小元数据包括：

```text
world_id
schema_version
world_time
commit_sequence
```

### 4.6 并发与版本

实体和关系使用 `revision` 进行乐观并发检查。候选基于 revision N 生成时，提交前必须确认相关记录仍为 revision N；否则放弃或重新裁决。并行 LLM 不得直接覆盖世界状态。

## 5. 生成与双验证工位

开放式生成被允许，但生成结果只是候选。建议采用以下职责分离：

```text
现实候选生成器
      ↓
┌────────────────┬────────────────┐
│ 验证工位 A     │ 验证工位 B     │
│ 世界/因果一致性│ 现实/体验可信性 │
└────────────────┴────────────────┘
      ↓
确定性收束器
      ↓
世界提交
```

### 5.1 验证工位 A：世界与因果一致性

主要检查：

- 使用的实体是否存在，或是否被合法创建；
- 身体、空间和对象状态是否支持该行动；
- 是否遗漏必要的行动前置步骤；
- 是否与已提交事实冲突；
- 是否无意中修改历史；
- 是否为了迎合当前输入而反向决定过去；
- 所有持久语义后果是否具有已提交的语义依赖。

工位 A 输出结构化 verdict 和 violations，不直接重写世界。

### 5.2 验证工位 B：现实与体验可信性

主要检查：

- 身体反应和行动尺度是否符合常识；
- 成功、失败或部分成功是否有充分依据；
- 环境反馈是否自然；
- 回应是否泄露主体不可能获得的信息；
- 是否带有不必要的游戏数值或系统报告口吻；
- 语言是否符合用户输入语言和主体的感知位置。

### 5.3 验证结果的处理

不采用简单的“两票通过即提交”：

- 任一工位发现硬冲突：拒绝该候选；
- 只有软问题：允许收束器降格或做受约束修正；
- 两者均认可：候选可进入收束；
- 两者分歧明显：最多再生成一轮候选；
- 重试后仍无可靠结果：使用最小、保守、不过度断言的结果。

保守不等于一律失败，而是只提交当前证据能够支持的最小现实变化。

LLM 可以生成、审查和建议，但没有直接提交权。

## 6. 小闭环与最小归档

每个 `ttd` 只需证明当前行动的局部闭环可信，不需要证明整个世界已经完整生成。

例如“下床去开门”的局部闭环可能包括：

```text
主体当前姿势
  → 腿部状态
  → 床与门的空间关系
  → 站立前置条件
  → 移动前置条件
  → 开门前置条件
  → 行动结果
  → 主体能够获得的反馈
```

闭环外的世界事实保持未确定。归档只写入：

- 经验证并收束的事件；
- 必要的实体状态变化；
- 必要的关系变化；
- 主体实际获得的观察或证据；
- 支撑上述结果所必需的最小依赖。

候选推理、内部评分、被否决结果和控制状态不进入世界事实。

## 7. 事实与呈现分离

自然语言呈现步骤只能读取：

- 已提交的行动结果；
- 已提交的状态变化；
- 主体实际获得的观察；
- 获准呈现的环境信息和风格元数据。

呈现器不能读取或泄露：

- 被否决的候选；
- 验证评分和内部推理；
- 未提交的潜在值；
- 主体尚无认识路径的隐藏世界事实。

呈现不能反向创造 WorldTruth。所有世界语义变化必须在呈现之前完成检查与提交。

## 8. 与 GWA 文档的对应

MVP 不要求一次实现全部 GWA，但保留下列不可破坏的方向：

- `ttd` 是意图，不是结果声明；
- Commit Before Expose；
- Query/Intent 不得为当前需要改写既有过去；
- 只提交当前操作的最小充分闭包；
- 精确事实、证据、认识状态和自然语言呈现相互分离；
- 世界语义值一旦解析就必须提交，纯程序中间值可以短暂存在；
- 并行模型可以提议和验证，单一提交边界决定世界状态。

## 9. 当前开放问题

后续讨论需逐步明确：

1. `ttd` 可接受的意识活动与行动范围；
2. 主体、身体、空间和对象的第一版最小 schema；
3. 局部闭环如何枚举及终止；
4. 硬冲突、软问题和保守降格的明确协议；
5. 两个验证工位的结构化输入输出格式；
6. LanceDB 原子提交、revision 冲突和回合恢复机制；
7. Cloudflare Workers AI 的模型分工、并行度、超时和失败策略；
8. SSH 会话、世界实例与主体身份的映射；
9. 同语言识别及呈现质量的最低验收标准。

这些问题保持开放，不阻碍将本文作为 MVP 架构讨论的共同基线。
