# MVP 卧室回合纵向切片 v0.1

日期：2026-08-23

## 已接通的路径

首个 MVP 回合只接受“起身 → 走到门边 → 开门”这一动作链。处理顺序为：

1. 将 `ttd` 文本规范化为有限动作；
2. 从固定卧室夹具解析站立与移动结果投影；
3. 对条件化候选做纯代码协议验证和资格判定；
4. 只把 eligible 候选交给 Mistral Small 3.1 审查；
5. 由代码选择最小承诺候选并检查投影 revision；
6. 将解析值及其 revision 连同不可变 commit package 原子追加到 LanceDB；
7. 让 Qwen3-30B-A3B 将已提交的玩家可见事实渲染成同语言自然文本。

陪审模型不能选择隐藏现实，也不能修改候选。渲染模型只接收已提交事件、状态变化与观察；调用失败时退回确定性中文渲染。

## 真实平台回归

使用本地忽略的 Cloudflare token 完成了一次端到端回归：

- 输入：`我下床走到门边开门`
- 选中候选：`bedroom-open-partial`
- 总耗时：约 6.85 秒
- LanceDB 确认提交：1 条
- 回应：`你从床边站起来，走到门边并打开了门。你的左腿有些不稳。`

回归没有把 token 写入日志、文档或数据库。

## SSH 纵向回归

使用临时 host key、临时密码和临时 LanceDB，通过标准 SSH client 完成了完整链路：密码认证 → PTY shell → `ttd:` → 中文动作 → Workers AI 陪审/渲染 → LanceDB 提交 → 再次显示提示符。

- 总耗时：约 2.27 秒
- LanceDB 确认提交：1 条
- 选中候选：`bedroom-open-partial`
- 临时凭据与数据库在回归后删除

## 当前边界

- 这仍是单一固定场景，不是通用世界模拟器；
- 候选目前由代码构造，尚未接入并行 Qwen 候选工位；
- 当前进程内写入串行化，尚未实现跨进程并发控制；
- SSH 界面已接入本地 MVP：密码认证、PTY、`ttd:` 行交互与 `exit`；默认仅监听回环地址；
- 自然语言渲染还没有机械式事实蕴含验证，因此它不是世界事实来源。
- 密码认证目前没有速率限制，服务因此默认只监听 `127.0.0.1`；
- `npm audit` 当前报告的 high 项来自 LanceDB 的可选 Transformers → Sharp 图像处理依赖链，并非新增 SSH 依赖；在升级路径明确前不做破坏性降级。

回合已封装为可恢复、顺序化的会话服务，SSH 层只负责传输。下一步应完成一次真实 SSH → Workers AI → LanceDB 回归，再决定公网暴露和认证方案。
