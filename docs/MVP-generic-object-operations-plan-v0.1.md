# MVP 通用对象操作层计划 v0.1

日期：2026-08-23  
状态：执行基线

## 目标

消除“门”和“纸条”各自拥有专用回合流程的问题，建立可被钥匙、纸条、杯子、抽屉等对象共同使用的最小操作层。

核心验收流程：

```text
ttd: 我拿起桌上的钥匙
ttd: 我打开床头柜的抽屉
ttd: 我把钥匙放进抽屉
ttd: 我关上抽屉
ttd: 我去开门
ttd: 我回来打开抽屉找钥匙
```

服务重启后，钥匙位置、抽屉状态和操作历史必须保持一致。

## 设计尺度

MVP 不实现完整 GWA，但遵守以下主轴：

- `ttd` 是意图，不是事实写入；
- LLM 无提交权；
- 先规范化、验证和提交，再向玩家呈现；
- 历史只追加，当前状态是历史的物化结果；
- 已提交事实不因查询顺序或模型上下文漂移；
- 只解析当前闭环需要的投影；
- 为 Evidence、认识变化和承诺依赖保留结构位置，但暂不展开完整系统。

## 实施步骤

### 1. 通用实体与世界视图

- 稳定实体 ID、类型、名称、别名和属性；
- 查询对象当前直接位置；
- 查询容器当前内容；
- 查询开关状态；
- 从 `world_commits` 完整重建；
- LanceDB 提交日志继续作为唯一权威源。

### 2. 事件驱动的时态关系

封闭承诺类型至少包括：

```text
entity_created
attribute_set
relation_asserted
relation_ended
```

物体移动必须结束旧关系并建立新关系。物化视图可以显示单一当前位置，但不能删除历史。

### 3. 通用对象操作协议

首批操作：

```text
observe
take
place
put_inside
remove_from
open
close
read
write
```

统一流程：

```text
前置条件检查
→ 条件化候选
→ 协议验证
→ 陪审
→ revision guard
→ 原子提交
→ 玩家可见回应
```

### 4. 小型卧室夹具

首批实体：

```text
self
bed-1
pillow-1
nightstand-1
drawer-1
key-1
blank-note-1
pen-1
door-1
```

类型能力来自 schema；当前是否可执行仍由位置、容器状态和本轮投影决定。

### 5. 最薄观察边界

引入结构化 `evidence_generated` 和 `epistemic_changes`。观察和读取回应只使用本回合批准的玩家可见 Evidence。暂不实现完整 Agent Epistemic Graph。

### 6. 意图与实体解析

确定性中文/英文模式先生成类型化意图，再将名称绑定到稳定实体 ID。零匹配或多匹配均明确失败，LLM 不得猜测对象。

## 验收项

- 拿取后旧位置关系失效；
- 普通物体不能同时有两个直接位置；
- 关闭容器阻止直接拿取内部物体；
- 打开后可以取出；
- 容器不能包含自身或形成循环；
- 同名对象产生歧义；
- 重启后恢复抽屉状态和钥匙位置；
- 既有开门与纸条回归保持通过；
- 真实 Workers AI 审查通过；
- 标准 SSH 多回合通过。

## 暂缓项

- 完整 Query Triage；
- 完整 Agent Epistemic Graph；
- 向量实体消歧；
- 任意开放式动作和复杂物理；
- 多进程写入；
- 公网 SSH；
- 独立实体/关系 LanceDB 物化表。

## 完成定义

新增普通物体或容器时，只需增加夹具实体和能力配置，不再新增专用回合处理器。
