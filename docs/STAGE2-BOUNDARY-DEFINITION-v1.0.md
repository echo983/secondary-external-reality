# 阶段2（正式内核）边界定义 v1.0

日期：2026-08-24
性质：决策记录，回应 `docs/STATUS-four-stage-maturity-assessment-v1.0.md` §6 剩余两条待决策之一（"阶段2的边界和契约内容谁来定、什么时候定"）。依据 `docs/PROBE-stage2-pack-loader-v1.0.md` 探针的真实发现，用户直接讨论确认。不是设计文档，具体每一项的实现方式在真正动手时另开设计文档。

## 1. 判断依据

阶段2的任务是"同一套机制，但要扛得住不是自己手搓的内容"。边界应该刚好覆盖"探针证明会卡住的地方"，不借机把所有能想到的通用性都塞进来——延续阶段1收尾时确认的核心原则：GWA/内核完备度按当前阶段自己的活儿打分，不预支未来可能用到的东西。

## 2. 纳入阶段2（有真实证据支撑）

1. **实体类型/属性 schema：字面量集合 → 可扩展注册表。** 这次仅加 `prop` 一种类型就已经要改 `worldSchema.ts` 源码；换一个主题世界（金庸/D&D/火星殖民地）几乎必然还要加更多类型，每次都改内核源码等于"内容污染内核"在 schema 层重演。
2. **新增"实体在地点里"的关系谓词**（占位名 `present_at`，最终定名留到实现时），并且明确它和 `located_on`（校验要求宾语必须是 surface/bed）语义分离。这是探针实测的真阻塞——不是可以晚点做的美化项，是现在直接抛 `MaterializedWorldError` 的洞。
3. **PlaceGraph 邻接从硬编码 TypeScript（`objectTurn.ts` 的 `PLACE_ADJACENCY`）变成数据。** pack 文件已经带着18条人工标注的邻接边，现在加载不进去；不解决的话每个新地点集合都要手写 TS 表，是结构层的同一个"内容污染内核"问题。
4. **把现有形状正式固定成对外契约**：实体/属性/关系/`WorldCommitment`/呈现包（`ApprovedPresentationItem` 等）的 shape，加上一条"以后只加不改不删"的版本号规则。这条更多是治理决定，不一定需要大改代码，但需要一份正式 spec——否则阶段3的加载器、阶段4的内容永远建立在"卧室 MVP 恰好长这样"的流沙上。

## 3. 明确排除阶段2（按需做，不预支）

- **自由文本叙事层 + jury 机制**——`docs/VISION-first-experience-instance-v1.0.md` 已经说明按需做；pack 里的叙事文本这次探针特意跳过，目前没有具体消费方（NPC对话/性格）需要它。
- **`observations: unknown[]` 类型化**——老技术债，和"扛得住外部内容"这个阶段2核心任务没有直接关系，继续挂着。
- **Zoom/Redirect 查询出口、NPC自主行为、对话语法**——这些是阶段3（引擎）该管的主题无关通用能力，不是阶段2契约的一部分。

## 4. 建议实现顺序（拆分，避免跨度太大）

按风险从低到高、依赖关系从底层到收尾排列：

1. **新增 `present_at` 关系谓词**——最小、最独立，直接解决探针发现的抛异常问题，不涉及现有代码路径的改动，风险最低。
2. **schema 可扩展注册表**——改变 `attributesByType`/`validateEntityType`/`validateAttribute` 的类型系统，是后续多个主题包的关键前提，风险中等。
3. **PlaceGraph 邻接改成数据**——涉及重构 `objectTurn.ts` 里已经稳定工作的 `PLACE_ADJACENCY`/`move` 校验逻辑（hallway/living-room 那套），风险中等偏高，需要仔细回归测试。
4. **对外契约文档化 + 版本号规则**——收尾工作，等前三步形状确定下来之后再写，不是独立的代码工作。

每一步各自验收（本地测试 + 真实模型 live-eval gate），像阶段1的每个 Layer B/C 里程碑一样单独提交，不合并成一个大改动。

## 5. 待定，不在这份文档里预先设计死

- `present_at`（或其他最终定名）的确切校验规则（是否也要防环、是否允许一个实体同时挂多个 `present_at`）；
- schema 注册表的具体 API 形状（运行时注册 vs. 编译期声明式表、要不要允许每主题包自带 schema 文件）；
- 对外契约用什么形式固定（TypeScript 类型 + 文档，还是加运行时 schema 校验）。
