# 四阶段态势评估 v1.0

日期：2026-08-24
性质：某一时刻的状态快照 + 决策记录，不是设计文档，不随代码变化持续维护——过时后应该被新的评估取代，不是被编辑更新。

## 1. 背景

`docs/GWA-larger-architecture-study-after-v0.9.md` 早就把完整 GWA 收窄成了一个"内核骨架"目标；这次 sdlpal 内容管线的工作把这个收窄再往前推了一层——发现"要不要实现 GWA 的某个不变量"不该是一次性、全局的判断，应该按下面这四个阶段、按每个具体作品的真实需要来决定。这份文档记录这次讨论达成的判断，供以后判断"现在该做什么"时对照，避免重新推导一遍。

## 2. 核心原则

**GWA 是服务于后续作品的理论工具，不是要交的作业。** 完备度不该拿"实现了多少 GWA"打分，该拿"当前这个阶段自己的活儿干完了没"打分。一个不变量现在没实现，只要架构形状留了口子、以后能加，就不是缺陷，是合理的延后。

## 3. 四个阶段

一个物理引擎→游戏引擎→游戏的标准分层，套在这个项目上：

1. **内核可行性实验品**——证明"规范承诺+认识内核"这套方法论的核心机制能不能立住。成功标准是架构可信度，不是好用/通用/健壮。
2. **正式内核**——同一套机制，但要扛得住"不是自己手搓的内容"：schema 可扩展、有稳定对外契约。
3. **引擎**（构建在正式内核之上）——和主题无关的通用能力：内容包格式/加载器、NPC 反应、对话语法、多主体规模化。
4. **可玩游戏**（构建在引擎之上）——某个具体主题的实际内容和真正能玩的体验。

## 4. 现状盘点

### 阶段1：内核可行性实验品——基本完工，可以考虑收尾

已完成：
- Layer A：SemanticAddress、typed Observation/Evidence/Acquisition、Query Triage 三路（固定读取/自由解析/认识边界）、呈现层批准数据包；四类结构化验收检查（Query Confluence、Commitment Closure Integrity、Minimal Resolution、Replay Determinism），全部有正例反例测试。
- Layer B 全部五项：PlaceGraph（4 节点线性链，故意封顶）、观察带宽（纸条精确内容需要够近）、主体物理够得着能力、记忆回忆（衰减但不改写 WorldTruth）、内涵式承诺重生成保真（独立于提交记录重新推导生成器）。
- Layer C 起了个头：多主体 Agent Epistemic Graph + 证言（第二个独立认识主体，转述不直接授权 WorldTruth）。

明确不补、按"用到再加"处理（不是待办清单，是记录判断本身）：
- 错误回忆/错误证言（"发现自己记错"——路线图成功判据字面写了这条，但近期不模拟复杂心理学，判断是对的取舍）；
- CausalSelectionBarrier（I3b）独立验证——现在靠生成器设计隐含满足，没有专门检查；
- Projective Consistency（I4）——现在没有分级投影内容，连测试对象都不存在；
- Zoom/Redirect 查询出口（Q4）、Explanation Model、呈现层 exposure provenance 审计、T5 语义因果类型强制、NPC 自主行为——都是纯设想，未动工。

判断：核心主张（同一投影多路径解析一致、认识只能走合法证据路径、可重放可回忆不改写过去）已经从多个独立场景反复验证过，继续在新场景上重复验证这条主张，边际收益已经不高。这个阶段本身的活儿基本干完，可以考虑正式收尾。

### 阶段2：正式内核——真空，连边界都没被定义过

这次做内容管线时才逼出来的具体缺口：
- 实体类型/属性 schema（`worldSchema.ts` 的 `attributesByType`）是给一间卧室量身定的封闭枚举，需要变成可扩展注册表，否则每换一个主题世界都要回头改内核源码，等于"内容污染内核"在 schema 层重演一次；
- 对外稳定契约——实体/属性/关系形状、`WorldCommitment` 形状、Query Triage 决策协议、呈现包契约，现在全部是"卧室 MVP 恰好长这样"，从没被正式固定成"外部代码可以放心依赖、不会说改就改"的接口；
- PlaceGraph 从故意做平的表升级成真图结构；
- `observations: unknown[]` 类型化——路线图很早点名、一直没动的老缺口。

判断：这一层现在唯一的"内容"就是这次讨论本身。它需要先被正式定义（哪些是这一层该稳定下来的契约），阶段3的加载器和阶段4的可玩性才有地方立足。

### 阶段3：引擎——刚起了个头，大部分是空的

已完成：
- 内容包交付格式 v0.1（`content-pipeline/pack-format/SPEC-v0.1.md`）——按行分隔、无嵌套、局部可恢复，刻意不用 JSON/YAML；配套解析器+序列化器，往返验证过。

未完成：
- 内容包→内核加载器——上次准备做，发现卡在"阶段2还没定义"，暂停；
- 三条内容来路的工具链：转换器（`sdlpal-import` 是第一个实例，本身也没做完——`SSS.MKF` 第2块的角色/物品记录还没解析）、人工手写工具（明确降优先级）、LLM 约束生成管线（概念上对应现有 interaction IR 审计那套机制，实际没搭）；
- NPC 反应/日程机制、对话语法（现在的语义 IR 是纯物体动作取向）、Zoom/Redirect 查询出口。

### 阶段4：可玩游戏——只有原材料，没有能玩的东西

已完成（`content-pipeline/sdlpal-import` 分支，独立于内核）：
- 《仙剑奇侠传》盛渔村+仙灵岛：地图瓦片（MKF+YJ1）解压验证过；`SSS.MKF` 的事件物体/场景表提取并互相印证过；定位出 18 个 Part1（灵岛求仙）地点；转换成 17 个地点、247 个实体的 `.pack` 内容包，配上原创名字/身份（明确不是原作角色，只借地点/花名册位置）。

未完成：
- 这份内容现在哪都接不进去——真要能用自然语言玩，`objectIntent.ts`（正则解析）、`renderer.ts`（呈现措辞）、interactionIr 提示词，整条自然语言链路都是针对卧室名词硬编码的，需要针对这份内容重新过一遍，完全没开始；
- 金庸/战国/怪奇物语/D&D/火星殖民地——纯概念，`docs/VISION-first-experience-instance-v1.0.md` 里的占位，没有实质工作。

## 5. 整体判断

阶段1 接近可以收尾的状态；阶段2 是真空但最该优先补上的一层，因为阶段3/4 都得先有它才立得住；阶段3/4 目前是零散的原材料和探路结果，没有连成一条线。

这次讨论里"感觉大跃进了"的准确诊断：**阶段2 被跳过了，阶段1 还没正式宣布收尾，就已经在阶段3/4 的方向上动手做具体实现了**（sdlpal 内容管线本身、"接入内核"那次被叫停的尝试）。往前探路本身不是错——"prop 类型缺失"这个阶段2 的真实需求就是靠往前探出来的，不探不会知道——但需要清楚意识到现在正处在这个状态，不要把探路结果误当成"阶段2/3已经完成"。

## 6. 待决策（不在这份文档里替用户定）

- 阶段1 是否现在就正式宣布收尾，还是先补 CausalSelectionBarrier 独立检查这类低成本、判据里明确点名的缺口再收尾；
- 阶段2 的边界和契约内容谁来定、什么时候定——是现在专门停下来做，还是继续靠阶段3/4 的探路倒逼形状；
- 内容管线（`content-pipeline/sdlpal-import` 分支）要不要继续往前探，还是先冻结在当前进度，等阶段2 有定论后再回来对接。
