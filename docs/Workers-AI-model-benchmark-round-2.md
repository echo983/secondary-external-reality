# Workers AI 模型基准 · 第二轮

日期：2026-08-23  
状态：探索性实验，不构成最终选型

## 目的

用六类 `ttd` 小闭环测试身体限制、空间阻挡、动作可行性、认识边界、尺度限制和社会行为。重点惩罚：擅自补事实、将困难判为不可能、把可能写成确定、替主体追加动作，以及无有效正文的 reasoning 消耗。

统一参数：`temperature=0.1`，`max_tokens=900`。所有模型收到相同的三行输出协议。

Qwen 使用 `chat_template_kwargs.enable_thinking=false`。Cloudflare 当前响应把其有效文本放在 `reasoning_content` 而非 `content`，runner 需临时兼容；GLM 未找到有效的关闭 thinking 参数。

## 测试集

1. 久坐后左腿明显发麻，立即站起并快步走三米开门；
2. 向外开的未锁木门被门外沉重书箱紧贴阻挡；
3. 右手端满热茶、钥匙在右侧紧身裤袋、左手空闲，尝试不放茶取钥匙开门；
4. 完全黑暗，只听到帘后缓慢呼吸，尝试仅凭声音确认身份；
5. 无工具、无抓点，尝试原地跳上两米石墙并直接站稳；
6. 无证件、证人或预先通知，声称是陌生守卫失散兄弟并要求立即相信和放行。

## 逐题观察

### 1. 腿麻后立即行动

- Qwen 没有真正裁决动作，只说腿麻未缓解，并擅自增加“行走以促进血液循环”的动机；
- Mistral 输出“可能跌倒”，保留了不确定性，但没有给出本轮实际收束结果；
- Llama 直接判定成功走到门边并开门，对明显身体限制过于乐观；
- GLM 无正文。

结论：所有模型都没有独立完成理想裁决。这类题需要候选集或显式的成功/部分成功/失败收束规则。

### 2. 门外木箱阻挡

- Qwen、Mistral、Llama 均正确判断门无法正常打开；
- Qwen 将输入中已有事实重复列为“新增事实”；
- GLM 错误地描述为门把手撞击木箱，混淆门板与门把手的空间关系。

### 3. 满杯热茶与右侧裤袋

四个模型都将动作判为无法完成，但这不是稳健结论：左手跨过身体伸入右侧裤袋虽然别扭，仍可能取出钥匙并操作门锁；真正应评估的是动作难度、热茶晃洒风险、裤袋紧度和锁的位置，而不是直接判定不可能。

这是本轮最重要的共同失败，说明模型容易把“困难或风险较高”压缩为“不能”。

### 4. 黑暗中的身份确认

四个模型均正确守住认识边界：仅凭普通呼吸声不足以确认具体身份。Mistral 和 Llama 输出最简洁。GLM 把“未确认身份”列为新增事实，需进一步区分世界事实与主体认识变化。

### 5. 原地跳上两米无抓点石墙

四个模型均正确拒绝直接站上墙顶。Qwen 把“跳跃高度不足两米”列为新增事实；这更适合作为本次事件结果，而非主体永久能力属性。GLM 引用了泛化的人类跳跃数值，但没有必要。

### 6. 让陌生守卫立即相信

- Qwen 直接判定不放行，结果合理但依然略有过度确定；
- Mistral 只判定不会立即相信，最符合输入中缺少守卫性格和规则的情况；
- Llama 直接确定守卫不相信，将怀疑程度收束得过死；
- GLM 无正文。

## 第二轮结论

### Qwen

关闭 thinking 后速度与成本极具优势，适合大量并行候选或初筛。但它会跳过关键过程、重复已有事实为新增事实，并快速做二元收束。目前适合作为候选工位，不适合单独提交世界。

### Mistral

综合表现仍最稳：格式可靠、正文简洁、较少胡编。不过它也会把困难误判为不可能，并且有时只给“可能发生”的范围而没有完成一次回合裁决。当前最适合验证或保守候选角色。

### Llama

速度和格式稳定，但价格高于 Qwen/Mistral，并且更容易把成功、失败或角色信念写得过于确定。暂未显示足够的性价比优势。

### GLM

在当前 REST 调用和预算下不可预测：部分简单题需要 600～850 个 reasoning tokens，另一部分 900 tokens 仍无正文。除非找到可靠的 thinking 控制，否则不适合在线 `ttd` 主链路。

## 当前选型假设

```text
Qwen（关闭 thinking）  → 低成本并行候选/初步分析
Mistral                → 可信性验证与保守修正
确定性收束器           → 处理“不可能 / 困难 / 不确定”的最终分级
Llama                  → 暂作离线对照
GLM                    → 暂停进入在线候选，等待 reasoning 控制方案
```

## 下一轮应测试

- 同一事实在连续三至五回合中的保持能力；
- 成功、部分成功、失败与“无法确定”的四级区分；
- 让 Qwen 产生多个候选，再由 Mistral 找硬冲突和过度断言；
- 验证模型能否指出“左手仍可能伸入右袋”这类反例；
- JSON schema 遵循率与字段级越权；
- 同一测试重复多次时的结论稳定性。
