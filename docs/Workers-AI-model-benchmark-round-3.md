# Workers AI 模型基准 · 第三轮组合流水线

日期：2026-08-23  
状态：探索性实验；当前流水线判定为不合格

## 目的

测试接近 MVP 的两阶段组合：

```text
Qwen（关闭 thinking）
  → 为同一 ttd 生成三个有实质差异的现实候选

Mistral
  → 拒绝越权候选
  → 在合格候选中选择承诺最小的一项
  → 或在全部不合格时返回 none
```

测试场景：跨身取钥匙、腿麻起身、钝刀砍树、黑暗身份确认、陌生守卫放行。

## 性能

- Qwen 平均约 2.46 秒；
- Mistral 平均约 4.89 秒；
- 单题串行组合的平均关键路径约 7.37 秒；
- Qwen 平均约 $0.000115/题；
- Mistral 平均约 $0.000352/题；
- 组合约 $0.000467/题。

两阶段均能稳定生成可解析 JSON；Qwen 的关闭-thinking文本仍位于 `reasoning_content`。

## 总体结果

Mistral 每题都选择了一个候选，没有一次返回 `none`。人工复核后，五个被选候选均仍包含不应直接提交的假设、额外动作或过度收束。

因此，本轮流水线不能进入世界提交路径。

## 逐题复核

### 1. 跨身取钥匙

Qwen 生成的三个候选都引入了额外结果，例如茶杯倾斜、无法保持茶杯稳定或主体选择放弃。

Mistral 选择 C：主体因为无法平衡茶杯而放弃。但“无法保持稳定”和“选择放弃”均未由输入决定。它还把候选 A 的“左手可以取钥匙”当作越权事实，却没有用同一标准审查 C。

正确处理应是：三个候选均需降格；当前信息最多支持“左手跨身取钥匙是可尝试但别扭的路径，是否成功及是否洒茶尚未裁决”。

### 2. 腿麻起身

Mistral 选择 B，但 B 擅自增加：

- 双手扶床沿；
- 缓慢站起；
- 步态不稳；
- 最终到达门前。

它还遗漏了用户目标中的“打开门”。Mistral 以“假设最少”为由选择 B，但没有识别这些额外动作和确定结果。

### 3. 钝刀砍白桦

Mistral 选择 A，并声称“刀具不够锋利、树皮较硬”符合题目。然而：

- “钝”支持刀刃不锋利，但不支持“刀具材质较差”；
- 未给出具体树皮状态，不能直接提交“树皮较硬”或“未侵蚀”；
- “浅痕”是合理候选，但仍应作为待裁决结果，而非从输入直接推出。

陪审员抓住了其他候选的角度和材质越权，却放过了被选候选中的同类问题。

### 4. 黑暗中确认身份

Mistral 错选 B：“可能是某人，但不能完全确定”。B 假设主体对多个人的呼吸模式有模糊记忆，这同样是未给事实。

C 的结果“无法确认身份”更接近认识边界，虽然其过程也不应擅自断言主体缺乏特定记忆。陪审员将“缺少足够证据”错误转化成了“任选一个低确定性身份猜测也可接受”。

### 5. 陌生守卫

三个候选分别确定了拒绝、犹豫或索要证据，实际上都需要守卫政策、性格或场景规则。

Mistral 选择“守卫犹豫并要求进一步验证”，理由是它承诺较小。但这依旧提交了守卫的心理和行为。若当前闭环必须回应，应先由世界层解析守卫反应，而不是由陪审员把最温和的虚构当作事实。

## 根因

### 1. “三个实质不同结果”会诱导虚构

当事实不足以区分三种结果时，强制多样性迫使生成器为每个分支制造隐含条件。候选中的 `assumptions` 很快变成未提交的世界事实。

### 2. 陪审员倾向于必须选一个

即使允许 `none`，Mistral 仍表现出选择压力：它会为相对温和的候选寻找理由，而不是一致地应用拒绝标准。

### 3. “最小承诺”不能只比较文风

较保守的措辞不等于较小的语义承诺。“守卫犹豫”听起来比“守卫放行”温和，但仍然决定了守卫的心理与行为。

### 4. 候选 schema 混淆了不同概念

本轮 `commitments` 中出现了“主体希望……”等意图，`assumptions` 中则装入未解析世界条件。需要拆分：

- 输入已有事实；
- 候选将新增的世界承诺；
- 候选依赖但尚未解析的条件；
- 主体意图；
- 主体可获得的观察。

## 架构修正

下一版候选不应直接给三个完整故事，而应给条件化结果：

```json
{
  "candidate_id": "A",
  "outcome_kind": "partial",
  "requires_resolution": [
    "self.left_leg.support_capacity_now"
  ],
  "conditional_on": [
    "support_capacity_now >= standing_requirement"
  ],
  "proposed_events": [],
  "proposed_state_changes": [],
  "observations": [],
  "new_world_commitments": []
}
```

建议的新流水线：

```text
Qwen
  → 枚举条件化候选与所需解析项

规则层
  → 删除依赖未声明事实却未列 requires_resolution 的候选
  → 合并语义重复候选

世界解析器
  → 只解析区分候选所需的最小世界投影

Mistral
  → 审查因果链与越权事实
  → 可以否决，不负责替世界选择隐藏条件

确定性收束器
  → 根据已解析事实选择候选并提交
```

## 第三轮结论

Qwen + Mistral 的模型分工方向仍有价值，但“生成完整结果 → 陪审员选一个”的协议不安全。模型不能替代隐藏条件解析，陪审员也不能拥有从多个可能世界中选择现实的权限。

下一轮应先测试条件化候选 schema，而不是继续优化提示词让 Mistral更会挑故事。
